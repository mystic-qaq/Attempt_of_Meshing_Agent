# Fluent 原理与跨案例进化：DrivAer 项目的实现边界

本项目需要同时改进观测、可执行动作和跨案例学习。给固定模型一个奖励描述，不会自动更新它的权重；记录失败也不会自动形成可靠策略。实际收益必须来自冻结条件下的原生对照。

Fluent 作为算法参考；本研究未取得同输入、同面积定义与同物理设置的 Fluent 原始网格对照。实验模型为 `deepseek-flash`。

## Fluent 的方法可以借鉴到哪里

Fluent 的优势包括几何准备、表面重建、局部尺寸控制、层碰撞处理和体网格过渡的完整工作流。其 scoped prisms 可以按区域设置，使用压缩与 stair stepping 处理碰撞，也提供保留首层偏移的选项。相关行为不能简单等同 snappy 的一个参数。[官方棱柱层文档](https://ansyshelp.ansys.com/public/Views/Secured/corp/v251/en/flu_ug/tgd_user_prism.html)

|方法|本项目的对应实现或实验|尚未实现的部分|
|---|---|---|
|可靠输入与几何容错|原生诊断与独立 CGAL 闭合、朝向、退化、自交证据同时记录；原始三角面不修改|自动判断哪些小通道可以在物理上忽略|
|表面重建 / wrapping|独立 CGAL Alpha Wrap 工具，加有界误差的双向 Hausdorff 检查；派生表面单独标记|可接受的真实汽车重建结果尚需验证|
|局部曲率与间隙尺寸|几何 BVH、局部查询、实测问题簇 ID 转坐标、细化到 surface+4 / 最高9级；实际资源门槛保持|曲率驱动的连续尺寸场、可靠的局部自适应采样|
|局部层碰撞处理|原生两种 shrinker、层叠/间隙测量、原始层数与实际厚度统计、完整流水线诊断|匿名面区的不同层策略、只压缩外层而保持首层的独立实现|
|平滑的层—体过渡|距离带、原生层平滑和过渡控制|Fluent Mosaic / poly-hexcore 的等价算法；没有复制其专有实现|

Wrap 会改变表面，不能因为它输出封闭模型就宣布几何保真。CGAL 的 alpha 控制可进入的细节/通道尺度，offset 控制外包距离；输出的有效拓扑不等于原始流道被保留。[CGAL Alpha Wrap](https://doc.cgal.org/5.6.2/Alpha_wrap_3/index.html)

实际诊断实验中，run_318 的 alpha=5mm、offset=0.1mm 重建产生4,175,548个三角面，但双向距离的保守上界为15.4403mm，超过预定1mm容差，因此拒绝进入网格对照。原始数据保留；该实验不是网格收益。

关于“Watertight Geometry 不支持 STL”的说法需要限定版本和导入路径。2024 R2 文档列出了 faceted geometry 导入限制；2025 R2 的 Import Geometry 文档明确支持在 Mesh 文件格式下导入 STL。[2024 R2 限制](https://ansyshelp.ansys.com/public/Views/Secured/corp/v242/en/flu_ug/tgd_user_workflow_guided_start_limit_wtm.html)、[2025 R2 导入](https://ansyshelp.ansys.com/public/Views/Secured/corp/v252/en/flu_ug/tgd_user_workflow_guided_tasks_import.html)

## 评价层覆盖时必须保留物理设计

新增报告同时记录 C1、C5、原始目标层数覆盖率、实际总厚度 / 原始目标总厚度，以及严重压缩面积。单批加层时，还计算首层推断的设计代理；多批切片时不套用单一等比公式来声称首层已测准。没有壁面剪切结果时不报告真实 y+。

可行 Pareto 集增加原始层数和厚度维度。“明显收益”除了原有10个百分点 / 20%单元数条件，还要求原始目标层数、设计代理和低于半目标厚度的面积不恶化超过2个百分点。把目标8层改成5层，不足以证明原设计改善。质量不合格的高覆盖结果仍不进入可行集。

DrivAerML 原始工作使用 ANSA HeXtreme，约1.6亿单元；近壁设置为7层、首层0.75mm、总厚12mm、变增长率1.2—1.4，求解器为 OpenFOAM。它不是“原始 STL 直接 snappy 一键成功”的证据。本项目早期先验为8层、首层约1.29mm、总厚约21mm，因此其间隙负担不同。若采用论文先验，应另冻结成相同物理设置的双路线实验。[DrivAerML 原论文](https://arxiv.org/html/2408.11969v1)

## 跨案例进化如何建立证据

[Voyager](https://github.com/MineDojo/Voyager) 的可复用技能库、[GEPA](https://github.com/gepa-ai/gepa) 的轨迹反馈与候选评估、[MemEvolve](https://github.com/bingreeky/MemEvolve) 的记忆内容/结构双循环，都提供设计参考。它们在各自任务上的成绩不能换算成汽车网格通过率。

当前实现为不可变的原生经验快照：记录源组、网格版本、无量纲几何描述、参数机制与真实结果。相似案例检索可附带同一源组的多种失败干预，但支持数仍只算一个原始车体；不跨案例复制坐标和面/簇 ID。派生几何与原始几何归为同一源组，训练与验证组必须分开。失败结果保持失败标签。

下一步演化对象应限于诊断顺序、测量策略和参数机制配方；验收器、预算、场景定义与数据分组固定。候选需要在至少两个独立训练车体和独立验证车体上，通过相同预算的原生比较，才能被提升为可复用策略。仅“写了一段反思”或“检索了旧日志”不能算进化收益。

当前没有运行通用 GEPA 优化器、训练新权重或完成 OPD，也没有经过验证的正向通用规则。OPD 应在教师已能稳定改善网格后，用学生自己的 rollout 接受教师纠正；本轮保存的可见状态/动作/结果只是前置数据。

## 实验顺序

先报告程序一次直出、固定程序反馈、模型反馈三条路线的所有尝试。分阶段修复与完整流水线诊断分别标记；后者用于检验表面处理和层构造的联合作用，最终质量/保真资格不变。重复输入、旧模板、额外计算与失败 API 请求分别计数。同一原始案例的所有版本继续共享 $0.50 上限。

取得首个合格修复后，再做无记忆 / 有记忆的源组隔离对照。只有在新车体上减少原生试验或取得更好可行网格，才能确认跨案例经验的价值。当前软件测试和独立输入资格改善只证明接口与判定更可靠，不证明 LLM 已优于程序控制。
