# V8：从真实 DrivAer 失败中修补 Harness

本版在独立分支开发。DrivAer 主对比继续使用冻结 V7，不能把本版改动后的测量或规划冒充冻结 Agent 的成绩。每条路线最多五次原生网格生成，复测缓存结果不重新运行 snappyHexMesh。

## 几何入口

新增 `--centre-geometry`：只把整个物体的包围盒中心平移到原点，保留全部三角面、轴方向、原文件和原始 source SHA。审计记录源坐标与 Agent 坐标的正反变换及往返误差；API 累计预算仍按原始输入哈希统计。所有后续局部区域使用记录的 Agent 坐标系。恢复旧计划时必须使用相同的坐标原点配置，不能直接套用另一坐标系的局部盒子。

这项可选操作用于处理坐标原点敏感的数值行为，不是自交修复；输入仍须通过原生检查。真实 DrivAer 的两个预先指定刚体原点都通过，原始原点有一处自交报告，这个案例仍记录为数值敏感性证据，不能宣称已经数学证明原始报告是假阳性。

## 原生操作空间

`SnapSpec` 增加 `n_face_split_interval`、`avoid_diagonal`、`concave_angle`、`min_area_ratio`；`LayerSpec` 增加 `layer_termination_angle`、`detect_extrusion_island`。这些参数分别涉及特征线与面边的对齐，以及部分邻面无法挤出时的层截断机制。原生 face splitting 默认关闭，启用时需要正整数间隔，不能大于 feature snap 迭代数。半个特征迭代数只是文档建议的起点。激进角部挤出可能产生共享边缺陷，不能按“覆盖更多”直接判为成功。

参见 [OpenFOAM snapping 文档](https://doc.openfoam.com/2306/tools/pre-processing/mesh/generation/snappyhexmesh/snapping/) 和 [原生面分裂及角部层生成说明](https://www.openfoam.com/news/main-news/openfoam-v3.0/meshing)。

生成时边界偏斜上限从 20 改为 4，与最终全局最大偏斜的门槛相配。新增 `generation_quality` 科学操作，只允许收紧当前生成约束；不能改变 `check_*` 验收字段、物理第一层高度或工况。恢复测量过的合法锚点仍是完整计划撤销，最终验收标准始终固定。

## 结构和空间反馈

最终提案按照实际提供给模型的嵌套 JSON schema 校验，未知参数、未知空间证据 ID、非有限数值和缺少的字段均不可进入原生计算。四轮对话中预留一轮修正机会：返回具体错误，要求模型修正，仍受同一 API 费用及轮数限制。不会通过改数值来替模型补一个方案。

冻结 Agent 的第二次原生尝试实际用了程序后备：模型一次提交两个 final plans，协调器报错而没有利用余下对话轮次合并。第四次原生尝试也用了后备：最终距离带不满足两个精细单元的最小支撑深度。V8 返回这些具体错误，允许模型在原四轮内纠正；生产协调器还强制对每个最终动作包执行只读 `preview_actions`，确认几何、计算量、物理尺度和场景认证。这个自动审计不额外调用付费模型、不生成网格。模型口述的数值或参数方向仍可能错；审计返回的计算尺度和原生测量才可作为证据。

同一源的刚体坐标版本通过有证据的 SHA256 别名计入同一累计 API 预算，防止从旧版预平移输入改为新版原始输入时重置 0.5 美元限额。别名仅按冻结源哈希、完整刚体变换记录注册，新的预算目录同步保留它们；循环或冲突映射拒绝付费调用。

`checkMesh` 有时把点夹连警告紧接在 Points 数量之后打印。旧解析器因此漏读 body 面数。新解析器保留实际面数，同时明确拒绝不连通的点面扇或共享边。它也拒绝基本检查写出“Mesh OK”但 body 表格写出 `multiply connected (shared edge)` 的结果。

原生 `nonManifoldPoints.vtp` 可以只有点、没有 VTK 单元。旧空间提取器只读单元中心，会遗漏位置。本版读取这种点集的实际坐标，并把非流形诊断纳入空间聚类，模型才有机会针对具体夹连位置规划。

## 边界测量

旧观察器要求每个边界多边形存在共同可见内点，因而无法表达某些合法的非星形凹多边形。本版保留原内点方法，并增加经过简单性、方向和面积验证的耳切三角化。解析闭合 U 形挤出体验证体积 14、面积 46；凹槽没有被凸包填平，原文件也没有修改。

本版仍拒绝投影自交、非相邻边接触、过度翘曲和开口/非流形边界。投影自交说明当前表示方法无法可靠测量，不能据此单独断言原始三维边界真实自交；也不能把拒绝测量的网格宣布几何保真通过。后验观察保留每个 native polyMesh 文件前后哈希，并独立调用原生 surfaceCheck。任何后验结果单独记录。

补充 `drivaer_native_observe.py` 对同一缓存网格使用 stock OpenFOAM 的 STL 三角化和独立表面检查；首先校验原始 OBJ 多边形边拓扑，禁止通过 STL 合并顶点掩盖裂口，再验证输出顶点没有移动或新增。采样保真指标复用同一函数和门槛。它只是独立复测工具，尚未替换冻结执行流程。

对直接第二轮缓存网格的原生诊断还发现：启用 `minTriangleTwist=0.01` 后有 219 个面不满足面内相邻三角片法向一致性。这与 tetrahedral quality、整体面法向 twist 或严格平面度不同。因此新增受限的 `min_triangle_twist` 生成操作；只允许从默认关闭状态收紧到非负值。文档提及正值有助于 Fluent 兼容性，不能把它解释为复现 Fluent 的层覆盖率。

## 验证边界

2026-10-11，计算节点运行93项测试全部通过，含明确数值边界、精简纠错上下文与预算别名回归。原始 DrivAer 的整体坐标入口通过原生检查，所有753,234面保留。冻结基准两路各五轮，Agent最高≥5面积覆盖35.45%，直接Codex最高57.00%，全部未通过完整验收；详见 [真实工程报告](../results/drivaer_20261011/REPORT.zh-CN.md)。

新版只读生产规划审计没有生成新网格。第一轮在线审计仍给出 min_face_weight=0.02，低于允许的0.05，校验器安全拒绝；随后新增明确允许范围和精简纠错上下文。最终在线审计遇到DNS解析故障，没有最终计划，故这次修补只有离线验证、尚无在线成功证据。同一原始几何的账本费用上界为$0.3917115，含DNS失败请求保守保留的$0.0520977；不等于平台实际账单。不得将新版测试称为修好了DrivAer网格。

单元检查覆盖参数可达性、不得放松质量、最终提案纠错、点集定位，以及闭合凹多边形的面积体积。直接路线的原生实验可以验证对应 Dict 控制被 stock OpenFOAM 执行；它不能替代“新 Agent 在未见真实几何上独立规划成功”的验证。

现阶段不得宣称 V8 已达到工业 RANS 可用。还需要独立真实工程输入、闭合可靠边界、足够的实际层覆盖、真实求解 y+ 与力/网格敏感性检查。本次 DrivAer 已使用的尝试必须累计，不能以换版本重置五轮限制。
