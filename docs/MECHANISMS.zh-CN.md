# 从 DrivAer 失败中改进科学工具

这次对比表明，“多写几条汽车经验”不足以解决问题。模型可能知道轮辋附近复杂，却混淆需要更多单元与层挤出空间不足；它也可能正确描述机制，但提出未命中坏点、已经覆盖的加密盒子或实际无效的参数。

本版没有部件识别或车轮规则，仍使用整个水密物体、匿名坐标区域和原生测量。大模型选择假设与数值，工具核算它的实际后果。

## 精确尺度及空间不足

`mechanisms.stack_height` 根据第一层完整高度、增长率和层数计算整个层叠厚度，也支持等厚层。`query_region` 现在返回局部名义单元宽度、有限向外法线命中的间隙、间隙内名义单元数、第一高度/单元比和两个相向等厚层叠的几何思考实验。加密单元可以增加分辨率，却不会增大间隙或缩短物理层厚。

这些不是原生 fluid medial distance。射线可能斜着命中或漏掉开口；没有有限命中代表未知，而非“没有间隙”。两侧壁面不一定要求相同层叠；工具报告风险而不强行替模型选参数或宣布物理不可行。Solid 半厚度只用于细节分辨率，不再把它混称为确定的 fluid gap。

## 补充缺失的原生控制

`gap_refine` 接收匿名盒子、minimum_cells、start_level、max_level。在 refinementRegions 中写入 stock v2412 的 gapLevel 和 gapMode outside，盒子的普通 level 为0；由原生检测到的狭窄间隙触发额外细化，不把整个盒子无条件加到最高级。

层级最多高于全局表面两级，目标3–8个单元；预测预算按整个盒子达到最高级和可能增加的局部壁面层计算。预算只是未校准的保守代理，最终实际单元上限与验收保持不变。outside 模式依赖一致向外的源表面绕向，可能根据方向排除单元；仍必须通过实际几何保真，不能当作补洞或修改输入的工具。

参数语义通过安装的 OpenFOAM v2412 refinementSurfaces.C 与 gap_detection 原生教程核查，亦可参见 [对应源码](https://api.openfoam.com/2412/refinementSurfaces_8C_source.html)。

## 在便宜预演里先发现无效干预

- 局部盒子必须与它引用的具体诊断区域相交，防止坐标原点或证据错配；允许只处理一个聚类的部分位置。
- 包含于已有同等或更强区域的重复加密不能再消耗原生轮次。
- 绝对首层高度下，仅改变已知未启用的 maxFaceThicknessRatio 会被拒绝；与有效控制联合调整时保留无效参数提示。
- 原生非流形点归为边界拓扑诊断，优先进入模型的有限上下文；几何原因仍是需要证实的假设。关闭两种 feature attraction 或单靠加密应对拓扑问题会收到警示，模型仍可以提交有根据的其他假设。
- 修正 check_min_face_weight 元数据的0.02为实际原生验收0.05。**实际验收没有变严或变宽**；此前元数据与执行不一致，可能误导规划，不能据此证明是模型错误的唯一原因。

完整最终提案仍须经过 schema、动作束和物理/场景预演，不能降低科学门槛。没有新增后训练或自动累积案例特例。

参数合法不代表推断合理。一次低成本只读审计中，模型把特征代理误当作4–6mm流体空间，而工具测到有限法线命中的间隙中位数146.3mm；它声称缩层降低相向层叠超限比例，但实测比例前后均7.63%。因此生产对话现在强制“两阶段提交”：先预演暂定方案，把实际尺度、警示与前后变化返给模型，再接收经过反证讨论的最终方案。四轮内预留最终复核和一次纠错机会；预算用完而未完成复核时不会采用暂定方案。复核完成仍不是物理正确性证明。

随后在线复核确实纠正了部分量纲混淆，但引入 base_cells 从8到14的全局改变，又引用此前的宽度和预算估计，最终超预算被拒绝。固定体积的名义体单元密度随该变化约增加(14/8)³=5.36倍。最新纠错上下文补全实际 domain/base_cells、预算和原生历史 Failed 数，预算错误返回候选级别、单元宽度与数值预测，避免只报泛泛“超限”。这次最终上下文修补已做软件验证，未继续付费重试。[完整审计结论](../results/mechanisms_20261012/PLANNER_AUDIT.md)。

## 工程完整性与验证范围

原生集成测试还暴露了默认 locationInMesh 路径引用已被移除的旧模块。现在默认 seed 位于源 bbox 上游、计算域内部，不依赖局部法线猜测，避免误选封闭内腔。发行版本与模块版本统一为0.9.0。

[闭合凹槽原生测试](../results/mechanisms_20261012/README.md) 仅验证新增控制在 stock OpenFOAM 中被执行，以及单元确实进入指定间隙；测试关闭层生成，没有大模型调用。它不能证明工业层质量或 Agent 闭环增益。DrivAer 的两路五轮结果保持原样，新版尚无独立真实工程闭环成功证据。
